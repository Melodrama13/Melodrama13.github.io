# 滚动与跳转

`src/composables/scrollNavigation.js` 统一负责活动列表、两种统计菜单和全局回顶按钮的滚动定位。页面组件负责选择目标、准备数据和保存位置，滚动器负责坐标、动画、布局校正与取消。

## 定位规则

- 同一滚动容器只有一个跳转请求。新请求取消旧请求及其动画；鼠标滚轮、触摸、指针操作和滚动按键也会取消自动校正。
- 目标必须属于当前容器。坐标根据容器边框、目标实际位置和遮挡高度计算，并限制在合法滚动范围内。
- 跳转先等待 Vue 更新及目标附近的重内容渲染，再滚动。布局稳定前按帧重新测量；活动页还等待正在进行的分批渲染。连续稳定 220ms 后结束，最多校正 5 秒。
- 边界请求每次测量实时顶部/底部。原生平滑动画结束后再修正坐标；用户开启减少动态效果时直接定位。

## 活动页

当期目标从完整活动数据中选择已经开始、开始日期最晚的数字 ID 活动，同一天以较大 ID 优先。因此排序和生日、生放送、联动显示开关不会改变当期目标。筛选排除了目标时，跳转清除阻挡定位的筛选；只有目标本身属于隐藏联动时才显示联动。事件跳转收起筛选面板，实际固定筛选区高度加 10px 作为偏移，并高亮目标行。

统计链接通过 App 更新 `jumpEventId` 和单调递增的 `jumpEventSeq` 后切换到活动页。EventHistory 在挂载、激活或属性更新时消费同一请求，不由 App 再启动重试。已消费的序号不会在用户取消或离开页面后重新执行。卡片来源 `EventID=0` 映射到初始卡行 `ori`；不存在的活动 ID 不触发滚动或改变筛选。

页面位置恢复与显式跳转互斥。新请求和手动滚动取消旧恢复；分批渲染的保位操作不会覆盖正在进行的跳转。离开页面取消导航，普通回到活动页仍恢复之前的可见行。

活动页的窗口重排与延迟行高变化由 `useViewportFocus.js` 按屏幕坐标校正。活动、生日和生放送行作为阅读对象，`content-visibility` 或分批渲染带来的迟到高度变化仍保持同一对象。返回页面时，有有效行锚点就只恢复该锚点，不再并行重放绝对 `scrollTop`；行锚点保存绝对屏幕 Y。分批渲染回调检查页面激活和取消代际，并让正在进行的保位或显式导航优先。

活动页的观察器通知合并到下一帧处理，避免在 `ResizeObserver` 回调内滚动触发 `content-visibility` 尺寸变化与观察器循环。预测编辑器开关优先固定所操作的可见活动行，并取消旧的激活恢复和布局恢复；从其他页返回后立即关闭编辑器也采用同一规则。

## 统计页与乐曲页

菜单共用 `useStatsNavigation.js`。手机端先折叠菜单、等待 Vue 更新，再定位；后续响应式重排由滚动器校正。子目标优先通过组件内部的 `data-scroll-anchor` 查找，再使用 DOM ID。目标上方保留 8px。

菜单按钮的 `data-nav-target` 和统计活动链接的 `data-event-id` 标记原始目标，便于定位故障与批量验收。它们不影响布局。

### 阅读位置与控件保位

三页共用 `useViewportFocus.js`。目标是让正在看的标题或局部内容留在原来的屏幕高度：导航展开、收缩和窗口缩放允许内容正常重排，保位不使用可视区域中线或整块高度比例。

- 缓存重排之前的 DOM 锚点和屏幕 Y；收到 `resize` 或 `ResizeObserver` 时使用缓存，避免把已经变化的坐标当作基准。
- 几何检测包含内容在滚动容器内的布局起点，排除实际滚动量；筛选栏等上方内容改变高度而内容宽高不变时仍能检测重排。
- 滚动事件同步更新快照，再在下一帧复核，避免滚动与重排发生在同一帧时沿用旧位置。
- 沿主内容的阅读列优先选择靠上的可见标题，标题不可见时选择阅读区域内的表格行、列表项或局部内容。保位结束仍保留同一锚点和原始 Y，直到用户滚动，避免连续缩放时换行、换列或累积误差。
- 页面内容控件引发布局变化时，优先固定被点击的控件。导航开关采用阅读锚点；导航目标点击则由显式跳转接管。
- 同一快照持续校正延迟布局，稳定 220ms 后结束，最多 5 秒。统计链接宽度和配队行高重算结束时立即校正，避免等到下一帧才补偿。
- 校正期间临时关闭浏览器原生滚动锚定，结束恢复原值；滚动坐标取整，避免 WebKit 为无法实现的亚像素位置反复校正。
- 鼠标滚轮和滚动按键先补齐尚未收到布局通知的重排，再取消保位并让用户滚动接管。普通指针按下直接取消保位；触摸按下只保留仍有实际位移的待补偿快照，确认发生滑动后才补偿，避免按钮在点击前移动。已补偿完成的稳定窗口不重放触摸起点；首次触摸事件之前已经发生的用户滚动量仍保留。
- 待补偿触摸与重排请求共用原生锚定抑制，最后一个请求结束才恢复原有样式。触摸期间的程序校正从用户滚动量中扣除，避免原生锚定或重复补偿造成误差。
- 原生滚轮、键盘和触摸滑动单独记录实际滚动量；延迟布局回调先把期望屏幕 Y 按用户滚动量更新，再补偿布局，自身校正不计入用户滚动。输入期间同样持有原生锚定抑制，真实滚动结束后切换到新的阅读对象，静止 800ms 作兼容兜底；开始滚动前的旧 `scrollend` 不结束新的输入。
- 触摸按下时即保存独立滚动基线，即使当时没有布局位移；按下后发生的重排和首个移动事件前已经执行的滚动量仍分别计算。未滑动的点击在触摸结束时释放基线，不补偿或移动点击目标。
- 显式跳转拥有优先权，并作废待处理的触摸快照。导航开始、完成或取消时同步通知保位控制器并更新阅读快照，不依赖可能迟到的原生滚动事件，避免跳转后被旧顶部或旧阅读位置追回。只有开始新跳转才清除原生输入基线；用户中断导航时保留该次输入刚建立的基线，避免吞掉默认滚动。KeepAlive 停用时解除监听和清空快照，激活时重新绑定。

页面顶部保留顶部；接近底部且内容缩短时，位置受合法滚动范围限制。多列变单列时固定所选阅读对象，其他列随正常排版移动。

## 本地验收

```powershell
node --test src/ui/scrollNavigation.browser.test.js
node --test src/ui/viewportFocus.browser.test.js
node --test src/ui/activityViewportFocus.browser.test.js
node --test src/utils/cardImageVariants.test.js src/utils/cardLimitedRules.test.js src/utils/compilationEvents.test.js src/ui/mobileTabSwitcher.test.js
npm.cmd run check:ui
npm.cmd run build
git diff --check
```

跳转验收覆盖 Chromium/WebKit、390/820/1440px、两种排序、八种辅助行开关组合、父子统计菜单、开服及其他统计活动链接、重复跳转、回页恢复和手动取消。回归测试遵循本仓库现有本地测试忽略规则。

焦点验收覆盖两引擎和两页的连续窗口缩放、显示卡面的导航开关、局部行、延迟布局、内容控件点击、快速缩放、KeepAlive 切换，以及手动滚动和显式跳转对保位的接管。最小夹具另外验证同任务内滚动后重排、重排通知前的滚轮接管、触摸按下与滑动分流，以及真实滚轮的默认滚动量。

活动页另行验证完整与分批渲染、普通阅读下的连续及快速缩放、KeepAlive 返回、筛选控件和卡片控件、延迟布局、手动滚动接管，以及顶部、底部和当期跳转。
